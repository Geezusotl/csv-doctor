# Benchmark results

Generated by `python -m benchmark.run`. Do not edit by hand.

## How this is measured

`benchmark/dataset.py` builds a clean 300-row people table, then injects a known set of errors into a copy and records each one (row, column, rule, and the value a perfect fixer would write). csv-doctor sees only the dirty file. A finding counts as correct only if its **rule, row and column** all match an injected error.

**Read this with one caveat:** the same person wrote the generator and the checks, so each injected error is a kind the tool was built to find. These numbers show the pieces work together and don't regress. They are *not* a prediction of accuracy on your own files. The last section shows what happens on valid-but-tricky data.

## Valid data that still gets flagged (known limitations)

Each case below is a column of *correct* values. Anything reported is a false positive.

| Case | Result | Why it matters |
|---|---|---|
| zip codes with leading zeros | no findings | numeric-looking text must never be rewritten |
| version-like labels | no findings | labels that differ by one tag are not typos |
| numbered groups | no findings | digits that differ are different labels |
| phone numbers | no findings | dashes inside digits are not dates or numbers |
| ids with a gap | no findings | sequential ids with one missing value |
| free-text names | no findings | names repeat but are not categories to correct |
| skewed salaries (lognormal) | flagged: outlier | real-world skew makes the median/MAD rule flag legitimate high earners |
| country code NA (Namibia) | flagged: missing_placeholder | 'NA' is a valid country code but is also a common missing-value marker |
| Ireland among Iceland | flagged: category_typo | a real, rare value one edit from a common one looks like a typo |
